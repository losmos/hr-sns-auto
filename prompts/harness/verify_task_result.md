# Verify Task Result

AGENTS.md, docs/harness/PROJECT_CONTEXT.md, docs/harness/HANDOFF.md를 먼저 읽어라.

## 목적

- 이 프롬프트는 이미 실행한 작업의 결과를 새 컨텍스트에서 다시 채점하기 위한 하네스 운영용 재사용 프롬프트이다.
- 작업 에이전트의 자기 보고가 아니라 실제 파일과 명령 실행 결과를 근거로 성공 기준 충족 여부를 판정한다.
- 검증 에이전트는 읽기 전용이며, 판정 보고서 1개 외에는 어떤 파일도 수정하거나 생성하지 않는다.

## 설정값

- `VERIFY_TARGET_PROMPT`: 검증 대상 작업 프롬프트 경로이다. 예: `prompts/tasks/some_task.md`.
- 이 프롬프트는 반복 실행용이므로 self-lock을 두지 않고 상단 값만 매번 대상 경로로 바꿔 실행한다.
- `VERIFY_TARGET_PROMPT` 값이 `TODO`이거나 비어 있으면 다음을 수행한다.
  - 어떤 파일도 수정하거나 생성하지 않는다.
  - 대상 프롬프트 경로를 지정해야 한다는 안내만 출력한다.
  - 판정 보고서도 만들지 않고 종료한다.

## 목표

- 대상 프롬프트의 성공 기준을 항목별로 추출한다.
- 각 항목이 실제로 충족됐는지 직접 확인한 증거로만 판정한다.
- 미충족 항목에는 후속 조치 제안을 남긴다.
- 검증 결과를 판정 보고서 1개로 남긴다.

## 판정 원칙

- default-FAIL로 시작한다. 추출한 모든 성공 기준을 우선 전부 미충족으로 둔다.
- 파일 내용 확인, 명령 실행 결과 확인 같은 직접 증거를 확인한 항목만 충족으로 바꾼다.
- 작업 에이전트의 자기 보고는 증거가 아니라 주장으로 취급한다. 자기 보고에는 run log 서술, `HANDOFF.md` 서술, 작업 에이전트의 마지막 출력이 포함된다.
- 자기 보고만 있고 직접 증거가 없으면 그 항목은 충족으로 바꾸지 않는다.
- run log를 참조한 경우, 참조했다는 사실과 그 내용을 주장으로만 사용했다는 점을 판정 보고서에 명시한다.
- 각 항목 판정은 충족, 미충족, 검증 불가(이유) 3단계로 남긴다.
- 직접 확인이 불가능한 항목은 검증 불가로 두고 그 이유를 적는다.

## 작업

1. `VERIFY_TARGET_PROMPT` 값을 확인한다. `TODO`이거나 비어 있으면 설정값 섹션의 안내만 출력하고 종료한다.
2. 대상 프롬프트 파일을 읽고 성공 기준을 항목별로 추출한다.
3. 각 성공 기준을 우선 전부 미충족으로 둔다.
4. 각 기준에 대해 직접 확인할 방법을 정한다.
   - 파일 존재나 내용은 파일을 직접 읽어 확인한다.
   - 특정 문자열, 경로, 섹션 유무는 `rg`로 확인한다.
   - 실행 결과가 필요한 기준은 읽기 전용 확인 명령으로만 확인한다.
5. 직접 확인한 증거가 있는 항목만 충족으로 바꾼다.
6. 직접 확인이 불가능한 항목은 검증 불가로 두고 이유를 적는다.
7. run log를 참조했다면 참조 사실을 기록하고, 그 내용은 주장으로만 사용한다.
8. 미충족 항목마다 후속 조치 제안을 적는다.
9. 판정 보고서를 `agent_outputs/reports/YYYYMMDD_HHMMSS_verify_<task>.md`에 생성한다.
   - `<task>`는 `VERIFY_TARGET_PROMPT`의 파일명에서 확장자를 뺀 이름을 사용한다.
   - 같은 이름 파일을 덮어쓰지 않는다.

## 판정 보고서 요구사항

- 상단에 검증 대상 프롬프트 경로와 검증 시각을 적는다.
- 성공 기준을 항목별 표나 목록으로 정리한다.
- 각 항목에 판정(충족 / 미충족 / 검증 불가), 근거로 확인한 파일이나 명령, 미충족 시 후속 조치 제안을 적는다.
- run log를 참조했다면 참조 사실과 주장으로만 사용했다는 점을 명시한다.
- 검증에 사용한 명령 목록을 남긴다.
- 최종 종합 판정을 전체 충족 / 일부 미충족 / 판정 불가 중 하나로 남긴다.
- 이 검증 작업이 `HANDOFF.md`를 갱신하지 않았다는 사실과 그 이유(읽기 전용 검증)를 남긴다.

## 주의사항

- 검증 도중 발견한 문제를 직접 고치지 않는다. 대상 파일 수정, 문서 수정, 코드 수정, 파일 생성, 이름 변경, archive 이동을 하지 않는다.
- 수정하고 싶은 문제는 고치지 말고 미충족 항목의 후속 조치 제안으로만 남긴다.
- 유일하게 생성하는 파일은 판정 보고서 1개이다. 그 외 어떤 파일도 만들지 않는다.
- `HANDOFF.md`, `PROJECT_CONTEXT.md`, `DIRECTORY_MAP.md`를 포함한 어떤 source 문서도 갱신하지 않는다.
- 대상 프롬프트가 요구하지 않은 기준을 임의로 추가하지 않는다.
- 확인 명령은 읽기 전용만 사용한다. 파일을 쓰거나 상태를 바꾸는 명령을 실행하지 않는다.
- 명령 예시가 필요하면 아래처럼 들여쓰기된 plain text로만 적는다.

    rg -n "성공 기준" prompts/tasks/some_task.md
    rg -n "특정 문자열" docs prompts
    git status --short

## 작업 후 확인

- 생성한 판정 보고서 경로를 확인한다.

    ls -t agent_outputs/reports/*_verify_*.md | head -n 1
    git status --short

- `git status --short` 결과에 판정 보고서 1개 외 다른 변경이 없는지 확인한다.
- 다른 변경이 있으면 읽기 전용 원칙을 위반한 것이므로 그 사실을 마지막 출력에 남긴다.

## 마지막 출력

1. `VERIFY_TARGET_PROMPT` 값과 검증 진행 여부
2. 성공 기준별 판정 요약(충족 / 미충족 / 검증 불가)
3. 최종 종합 판정(전체 충족 / 일부 미충족 / 판정 불가)
4. 미충족 항목의 후속 조치 제안
5. 생성한 판정 보고서 경로
6. `HANDOFF.md`를 갱신하지 않은 이유(읽기 전용 검증)
